# Installation and operations

## Local configuration

The application source lives in `app/`. It uses a traditional MySQL connection via Laravel PDO; it does not use a hosted database service. Current local configuration targets `127.0.0.1:3306`, database `forma_construction`, Laragon's local `root` account with an empty password. This is a local testing convenience. Do not use this database account in production.

Create your own `.env` from `.env.example`. Keep it private. `APP_KEY` is generated by `php artisan key:generate`; do not regenerate it on an established installation because encrypted sessions and other encrypted data will be invalidated.

```dotenv
APP_NAME="Your Construction Business"
APP_ENV=local
APP_DEBUG=false
APP_URL=http://127.0.0.1:8000
APP_TIMEZONE=Asia/Singapore
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=forma_construction
DB_USERNAME=root
DB_PASSWORD=
SESSION_DRIVER=database
SESSION_LIFETIME=60
SESSION_ENCRYPT=true
```

`APP_NAME` identifies the framework application; the visible business identity is edited in Business settings. Change `APP_TIMEZONE` before entering dated records; existing timestamps are not migrated between time zones.

## Manual setup

From `app/`:

```powershell
composer install
Copy-Item .env.example .env  # only if .env is absent
php artisan key:generate
php scripts/create-database.php
php artisan migrate --seed
php artisan workspace:admin owner@example.com --name="Business Owner"
php artisan serve --host=127.0.0.1 --port=8000
```

The normal seeder inserts business defaults; it creates no user. Run the seeder during initial setup only: it resets the default business name, currency and accent. The demo seeder is optional, refuses production environments and skips when projects already exist. Never run `migrate:fresh` against business data.

## Laragon virtual hosts

Use Apache/Nginx from Laragon or the included development server, not both on the same port. Set the virtual host's document root to the absolute `app/public` path. For Apache enable `mod_rewrite` and `AllowOverride All` so Laravel's supplied `.htaccess` can route requests. For Nginx use `try_files $uri $uri/ /index.php?$query_string;` and forward only `index.php` to PHP-FPM; deny hidden files and other PHP files.

No `npm install`, `npm run dev` or `storage:link` is needed. Private files are served only by application download routes. The default SVG logo and illustration are original code assets; no third-party image license is required.

## Upload limits

Application documents: up to 10 MB. Logos: up to 2 MB. Set PHP `upload_max_filesize=12M` and `post_max_size=16M` or higher, and align the web server's request body limit. Restart Laragon after changing PHP configuration. Ensure `storage/` and `bootstrap/cache/` are writable by the web process; do not grant broad permissions to the rest of the checkout.

## Testing MySQL

Create `forma_construction_test` as an empty MySQL database using Laragon's database manager. The provided test configuration overrides the database name; it inherits host and credentials from the environment. Then run:

```powershell
php artisan config:clear
composer test:mysql
```

Integration tests migrate and roll back the dedicated test database. The working `forma_construction` database is separate. For routine development, `php artisan test --compact` uses in-memory SQLite regardless of your `.env` database.

## Backup and recovery

Back up the MySQL database, `storage/app/private`, and the private `.env` (including `APP_KEY`) together. Use a MySQL account with backup permissions and a protected client option file instead of putting a password on the command line. Example from MySQL's bin directory, replacing absolute file paths:

```powershell
.\mysqldump.exe --defaults-extra-file=C:\secure\mysql-backup.cnf --single-transaction --routines --triggers --result-file=C:\secure\forma-backup.sql forma_construction
```

Protect and encrypt backups, restrict access, and test restoration into a separate schema. Stop writes or enter maintenance mode during coordinated database/file snapshots. Restore SQL with a MySQL client, restore private files to their matching paths, restore the original key, update `.env` for the destination, run `php artisan optimize:clear`, and verify sign-in, reports and document downloads. Never restore a backup over an active business schema without an explicit recovery plan.

## Deployment

Use PHP 8.2+ and MySQL 8.0+, a dedicated database user, TLS, `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL=https://your-domain`, `SESSION_SECURE_COOKIE=true`, and a strong `APP_KEY`. Install with `composer install --no-dev --optimize-autoloader`, run reviewed migrations with `php artisan migrate --force`, and warm caches with `php artisan config:cache`, `php artisan route:cache`, `php artisan view:cache`. Never deploy demo accounts. The Artisan server is for development only. No background queue is required by the current features.

## Troubleshooting

| Symptom | Resolution |
| --- | --- |
| Connection refused | Start MySQL in Laragon; verify host/port in `.env`. |
| Access denied | Check database username/password and schema permissions. |
| Unknown database | Create schema in Laragon or run `php scripts/create-database.php`. |
| Missing tables | Run `php artisan migrate --seed` on a fresh installation. |
| Blank/error page | Check `storage/logs/laravel.log`; keep debug disabled outside private development. |
| 419 after a long idle period | Refresh and sign in; the session or CSRF token expired. |
| 403 | The role cannot perform that action, or a financial record is protected. |
| Upload rejected | Check allowed types, actual content, size and PHP request limits. |
| Changes to `.env` ignored | Run `php artisan config:clear`. |
| Documents missing after restore | Restore private storage along with the matching database backup. |
| Port 8000 busy | Stop the other process you own, or serve on 8001 and update the URL. |
